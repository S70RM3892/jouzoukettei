# jouzoukettei — 有機構造決定パズル

京大化学の有機（大問3の構造決定）で使う「条件から候補を絞り込む推論」を反復訓練するブラウザゲーム。
仕様は Claude Docs の「有機構造決定パズル 仕様書」。

| モード | 内容 | 問題数 |
| --- | --- | --- |
| 絞り込み型 | 分子式と手がかりカードから、候補を消して1つに決める（C₅以下の脂肪族） | 20 |
| 大問型 | C₁₂〜C₂₀ のエステル・アミド・ペプチドを加水分解 → 切れた結合の数 → 断片ごとに絞り込み → 部分加水分解で組み立て | 8 |
| 数え上げ型 | 条件を満たす構造異性体と立体異性体の数を答え、全異性体で答え合わせ | 10 |
| 高分子型 | 平均分子量から重合度と結合の数を計算 → 加水分解で得た単量体を絞り込む（ナイロン66・ナイロン6・PET・ポリ乳酸・ポリ酢酸ビニル・アラミド） | 6 |
| 京大レベル | 京大の過去問の答え X を同じ手順で問題化した「再現」と、その難易度帯に入る自動生成の大問。水素付加量・燃焼分析の計算つき。毎朝5時に入れ替わる | 8＋12 |

## 遊び方

`dist/index.html` をブラウザで開くだけ。サーバーもネット接続もいらない（フォントだけ Google Fonts から読む）。
`dist/` は GitHub Actions が自動で生成してコミットする。

1. 問題を選ぶ（難易度 ★1〜★3、または「おまかせ」）
2. 手がかりカードをタップして結果を見る。問題ごとに「最少で何枚あれば決まるか」を表示し、それより多く開いた分だけ1枚 −10 点
3. 矛盾する候補を自分で消す（左右スワイプか「消す」）。自動では消えない
4. 残り1つで「確定」。誤答なら矛盾したカード、根拠なしで消した候補は消すべきだったカードが出る
5. 間違えたカードの種類が「復習リスト」に溜まり、おまかせ出題で多めに出る

23時〜5時はプレイできない（仕様書の運用ルール）。

## 構成

| パス | 役割 |
| --- | --- |
| `problems/narrow.json` | 絞り込み型（仕様書の JSON 形式＋`level`） |
| `problems/big.json` | 大問型（`fragments` と `assemble`） |
| `problems/polymer.json` | 高分子型（`unit` は * で端を示した繰り返し単位、`n` は重合度、`bondsPerUnit` は縮合で外れる H₂O の数） |
| `problems/count.json` | 数え上げ型（`pool` はその分子式・分類の異性体すべて、`expect` は教科書の数） |
| `problems/names.json` | 結果画面に出す物質名 |
| `src/chem.js` | 手がかりカードの判定ロジック（SMARTS・酸化/加水分解/オゾン分解・不斉炭素・シス-トランス） |
| `scripts/test-rules.js` | 判定ロジックの単体テスト（教科書の典型例） |
| `scripts/validate.js` | 問題の自動検証 |
| `scripts/build.js` | 検証 → 構造式SVGと判定表を前計算 → `dist/index.html` を出力 |
| `src/index.html` | ゲーム画面のテンプレート |
| `src/enumerate.js` | 分子式から構造異性体を漏れなく列挙する（候補集合・数え上げの母集団） |
| `src/calc.js` | 燃焼分析・元素分析・分子量・気体の体積の計算 |
| `src/generator.js` | 京大レベルの大問の自動生成（下の「自動生成のしくみ」） |
| `data/kakomon.json` | 京大 2006〜2026 年度（手元にある 16 年分）の有機の出題要素をタグと自分の言葉の要約にしたもの、と構造決定の答え X。問題文は写していない |
| `scripts/forecast.js` | 出題要素の予測と、時系列の後ろ向き検証（`generated/forecast.json`） |
| `scripts/generate.js` | 京大の X で難易度の物差しを作り、日付を種に問題を作って `problems/generated.json` に書く |
| `scripts/test-kakomon.js` | 京大の過去問の設問をエンジンだけで解かせ、京大の答えと一致するか確かめる |
| `scripts/test-enumerate.js` | 異性体の数が教科書の数と一致するか |

化学処理（RDKit）はビルド時に Node で行い、ブラウザには前計算した構造式SVGと判定結果だけを埋め込む。
仕様書ではブラウザで RDKit.js を CDN から読む案だったが、wasm 読み込みが不要になり、スマホでも一瞬で開けてオフラインでも動くのでこちらにした。

## 問題を足す

```sh
npm install
npm test          # 判定ロジックのテスト + 全問題の検証
npm run build     # dist/index.html を作り直す
```

検証スクリプトが確認すること（1つでも落ちた問題は収録しない）:

1. 全候補の分子式が `formula` と一致する
2. 候補に重複がない（canonical SMILES で比較）
3. 全手がかりを適用すると、候補が `answer` の1つだけ残る
4. どの手がかりも、単独で候補を1つ以上消す
5. 手がかりの `result` が、正解の構造に実際にカードを当てた結果と一致する
6. カードが適用できない構造（例: C=C を持つ候補に KMnO₄）を含まない
7. 大問型: X の加水分解生成物と断片が一致し、原子の収支（X ＋ n H₂O）が合う。組み立ての候補はどれも同じ断片に分かれる
9. 高分子型: 繰り返し単位 ＋ `bondsPerUnit` H₂O と単量体の合計で原子の収支が合う
8. 数え上げ型: 母集団が重複なく所定の数そろっていて、答えの数が `expect`（教科書の数）と一致する

## 自動生成のしくみ（京大レベル）

1. **断片ライブラリ**: アルコール・ジオール・カルボン酸・芳香族カルボン酸・フェノール・アミン・カルボニル化合物など 14 分類について、分子式ごとに構造異性体を全部列挙する。候補集合に漏れがないので「全部考えたか」が試される
2. **型**: ジカルボン酸のジエステル／ジオールのジエステル／エステル＋アミド／ジアミド／グリセリンのトリエステル／ビニルエステル（加水分解でアルデヒドやケトンが出る）の 6 型。京大の X 8 題（2006・2007・2008・2010・2013・2016×2・2017）はすべてこの 6 型のどれかで作れる
3. **手がかり**: 断片ごとに「答えがちょうど1つに決まる最小のカードの組」を総当たりで探す。1枚で決まるカードは使わない（京大と同じく、条件を組み合わせないと決まらないようにする）。カードで決められない構造は出題しない
4. **組み立て**: つなぎ方が複数あれば、部分加水分解の生成物や不斉炭素で決めさせる
5. **計算**: X の水素付加量（標準状態の体積から C=C の数）と、断片 1 つの燃焼分析（CO₂・H₂O の質量から分子式）。丸めた数値から分子式が一意に戻ることを確かめてから出す
6. **難易度**: 候補数の情報量・手がかりの数と種類・立体・与えられた規則・組み立て・計算・炭素数から点数をつける。京大の X を同じ手順で問題化して測り、**京大の下位 25% 〜 最大の 1.25 倍** に入ったものだけ採用する

### 当てる練習（後ろ向き検証）

どれも「その年より前のデータだけで、その年を当てる」形で測った。

| 対象 | 方法 | 結果 |
| --- | --- | --- |
| 出題要素（33 タグ）| 出現頻度 / 減衰と間隔を調整したモデル / 前年コピー | 的中率（R 精度）47.4% / 43.5% / 35.6%（当てずっぽう 35.1%）→ 単純な出現頻度を採用 |
| 大問の型（6 型） | 一様 / 過去の型の割合 / 出題予測 / 半々 | 実際の型に付けた確率 17% / 13% / 20% / 16% → 出題予測を採用（検証できたのは 6 題だけなので差は参考程度） |
| エンジンの到達範囲 | 京大の設問 27 個をエンジンだけで解く | 27/27。解けない出題要素 7 件（アセタール交換、メチル化分析、フィッシャー投影、イミドの位置選択、選択的アセチル化、配向性と合成経路、ジアリールエーテルの水素化分解）は `npm run test:kakomon` で一覧が出る |

調整したモデルが単純な頻度に負けたのは、16 年分では細かい調整が過去に合わせすぎになるため。勝った方を自動で選ぶようにしてある。

```sh
npm run forecast                   # 出題予測と後ろ向き検証
npm run generate -- 20260929 12    # 種 20260929 で 12 問（省略すると今日の日付）
```

GitHub Pages の workflow は毎朝 5:00（日本時間）に、その日の日付を種にして作り直して公開する。
リポジトリに 60 日間 push がないと GitHub が定期実行を止めるので、そのときは Actions 画面から有効に戻す。
